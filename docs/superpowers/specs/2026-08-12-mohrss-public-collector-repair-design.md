# 中国公共招聘网公开岗位采集修复设计

**日期：** 2026-08-12  
**范围：** `mohrss_public_jobs` 公开岗位采集、暂存和质量验收

## 1. 目标

恢复中国公共招聘网公开岗位的低频采集能力，增加第二个全国公共招聘来源，降低现有岗位库对单一域名的依赖。首轮只执行最多 20 条岗位的冒烟采集；结构、合规和质量报告通过后，才允许提交合格记录并逐批扩大数据量。

## 2. 已核验的公开访问流程

平台公开岗位列表采用两步匿名访问：

1. 访问 `/cjobs/jobinfolist/listJobinfolistIndex`，取得公开页面和匿名会话 Cookie；
2. 使用同一匿名会话访问 `/cjobs/jobinfolist/listJobinfolist`，通过 `textfield` 提交岗位名称关键词，通过 `searchtype=gw` 指定岗位检索。

该流程不使用账号、登录态、验证码、请求签名、设备指纹或私有接口。匿名 Cookie 只保存在单次采集进程的内存中，不写入日志、快照或批次报告。

## 3. 适配器修复

- 新增公开列表入口的预热请求，并将其计入请求预算和限速。
- 字符串查询改为 `textfield=<岗位关键词>` 和 `searchtype=gw`；`ACB241` 继续只表示薪资条件。
- 站点实际每页返回 20 条记录，`pagecount` 与 `totalpages` 表示总页数，`totalcount` 表示总记录数。列表解析按这套语义校验分页。
- 详情页继续使用已审核的 `/cjobs/jobinfolist/cb21/showgw?id=<岗位编号>` 路径，并只接受跳转到 `/cjobs/htmls/cb21gwPages/<岗位编号>.html`。
- 详情解析、个人联系方式清理、来源 URL 校验、发布时间证据和原始快照继续复用现有门禁。

## 4. 数据流程

公开首页预热 -> 岗位族关键词列表请求 -> 公开岗位详情 -> 原始响应快照 -> 统一字段规范化 -> 岗位族证据识别 -> 日期与质量门禁 -> 去重 -> `staged/review/quarantine` 三类结果 -> 人工确认提交 -> 知识库和知识图谱重建。

检索关键词只用于发现岗位，不作为岗位族证据。只有岗位标题和职位描述达到现有分类门槛的记录才能进入 `staged`；证据不足的记录留在 `review`，不得因数量目标自动转正。

## 5. 安全与停止条件

- 维持来源注册表中的 5 秒最小请求间隔。
- 首轮上限为 20 条记录、20 页和 100 次请求。
- 出现 `401`、`403`、`429`、验证码、登录页、异常重定向或页面结构变化时立即停止该来源。
- 不采集求职者信息，不保存联系人、电话、邮箱、Cookie 或其他会话材料。
- 不扩大到来源注册表之外的域名和路径。

## 6. 测试与验收

先用本地固定样本补充失败测试，再实现最小修复。测试至少覆盖：匿名预热请求、正确检索字段、分页语义、Cookie 不落盘、请求预算、详情跳转白名单、结构异常停止和现有隐私清理。

实现后按以下顺序验收：

1. 运行适配器和采集服务测试；
2. 运行最多 20 条的实时低频试采；
3. 检查有效、复核、隔离、重复、岗位族和日期可信度统计；
4. 只提交通过门禁的新增唯一岗位；
5. 重建知识库、知识图谱和验收统计；
6. 运行完整测试和代码检查。

首批成功标准是公开流程稳定、批次证据完整且至少产生可解释的正式增量。若没有记录通过质量门禁，保留审计结果并停止扩大批次，不通过降低标准补数量。
