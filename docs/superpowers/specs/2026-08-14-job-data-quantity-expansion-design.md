# 岗位数据数量优先扩充设计

日期：2026-08-14  
适用项目：XH-202621 多源异构数据驱动岗位和能力图谱构建与动态演化分析研究  
方案：A - 数量优先、宽进严出

## 1. 背景与现状

比赛要求系统提供至少 100 条岗位 JD 及测试用例，并量化验证 JD 解析、简历提取和人岗匹配准确率均不低于 90%。项目内部进一步设定了 5,000-10,000 条有效唯一 JD、22 个岗位族全覆盖、多源交叉验证和动态演化分析目标。

2026-08-14 审计结果如下：

- 主数据库包含 2,568 条岗位记录，其中 1,318 条通过现有质量门，553 条重复，692 条待审，5 条隔离；在这 1,318 条记录中，只有 546 条同时具备可信发布日期且位于 2022-2026 年，按本方案口径可计入最终有效总量。
- 1,318 条有效记录中，1,309 条来自智联招聘历史文件，单一来源占比约 99.3%。
- MLOps 工程师、多模态工程师、提示词工程师、AI 解决方案工程师四个岗位族当前为零。
- 根目录三批岗位文件共 4,893 条，但不能直接作为有效数据：
  - `jd_raw1.jsonl` 共 2,100 条，当前分类器可自动确认或重新分类约 882 条；
  - `智联测试.jsonl` 共 2,099 条，当前分类器可自动确认或重新分类约 277 条，其中 1,768 条发布日期不在 2022-2026 年或缺失；
  - `jd_raw.jsonl` 共 694 条，全部缺少可信发布日期，当前分类器可自动确认或重新分类约 112 条。
- 搜索关键词曾被当作岗位标签使用，已发现“以 Java 为搜索词获得的 C 语言嵌入式岗位被标成 Java”等误分类。
- 当前数据库没有正式的原始页面快照记录，来源追溯证据不足。

因此，方案 A 不把“已获得的搜索结果条数”等同于“有效岗位数据条数”，而采用大量合规原始数据进入、严格质量门筛出的数量漏斗。

## 2. 目标与非目标

### 2.1 目标

1. 新增约 8,000-9,000 条具有明确授权依据的原始 JD。
2. 最终形成不少于 5,000 条有效、唯一、可追溯的 JD；冲刺目标为 5,400 条。
3. 覆盖配置中的 22 个岗位族，每个岗位族至少 100 条有效唯一 JD。
4. AI 智能体应用工程师和 Java 开发工程师各保留不少于 500 条有效唯一 JD，用于比赛样板演示。
5. 有效数据覆盖 2022-2026 年，并能支持至少三个时间窗口的动态演化分析。
6. 有效数据至少来自 8 个来源域和 3 种来源类型，单一来源占比最终不高于 35%。
7. 每条正式入库记录均保留授权依据、来源标识、原始文件哈希、处理批次、质量判定和审计轨迹。

### 2.2 非目标

- 不自动抓取 BOSS 直聘、智联招聘、前程无忧、猎聘、拉勾等商业招聘平台。
- 不绕过登录、验证码、Cookie、签名、访问频率限制或反自动化措施。
- 不采集或导入真实候选人简历、姓名、电话、邮箱、身份证号等个人信息。
- 不把 AI 生成的 JD 混入真实市场岗位数据。
- 不为了达到数量而放宽岗位相关性、日期可信度、重复治理或来源授权要求。
- 本轮不改变简历解析、匹配算法和前端交互功能，除非为展示数据质量审计所必需。

## 3. 数据来源策略

来源按以下优先级接入：

1. **授权平台离线导出**：由团队提供平台或数据权利方的书面授权、授权清单和原始导出文件。系统只进行本地导入，不访问文件中的岗位链接。
2. **合作企业直供**：企业 HR 或 ATS 管理员导出企业自有历史 JD，并授权用于本比赛研究、测试和演示。
3. **企业官方招聘门户**：仅接入已经完成公开访问、路径范围和合规状态审核的中国企业招聘站点；严格按来源配置的路径、页数、记录数和访问间隔运行。
4. **政府及公共就业服务平台**：仅使用无需登录、公开可访问且已经登记审批的岗位列表与详情接口或页面。

每个来源必须具有独立的 `source_id`，并在来源注册表中记录来源类型、市场范围、允许路径、采集方式、授权或合规状态、解析器版本和数量上限。未获批准、授权材料缺失或授权范围不明确的来源不得进入正式数据管线。

## 4. 数量漏斗与配额

### 4.1 总量漏斗

| 阶段 | 目标数量 | 说明 |
| --- | ---: | --- |
| 新增原始数据 | 8,000-9,000 | 允许包含重复、误检和待审记录 |
| 结构与来源校验通过 | ≥7,500 | 字段可解析、来源在授权范围内 |
| 岗位相关性与日期通过 | ≥6,000 | 2022-2026 年，标题与能力证据支持岗位分类 |
| 去重与质量门通过 | ≥4,454 条新增 | 与现有 546 条可信时序记录合并后达到 ≥5,000 条 |
| 冲刺总量 | 5,400 | 在不降低质量门的前提下争取 |

若新增批次合格率低于 55%，停止继续扩大同类来源，先修订查询词、导出条件或来源组合。不得通过重复导入、降低阈值或改写发布日期补足数量。

### 4.2 岗位族配额

- 22 个岗位族均须达到至少 100 条有效唯一 JD。
- 当前为零的四个岗位族优先补齐到 120 条以上，以抵消后续抽检和去重损耗。
- AI 智能体应用工程师和 Java 开发工程师最终各不少于 500 条。
- 其余新增记录优先填补有效数量低于 100 的岗位族，再按岗位族缺口比例分配。
- 当一个岗位族达到目标后，采集调度应自动降低其优先级，避免 Java、前端等高频岗位挤占总量。

### 4.3 时间配额

- 正式动态演化数据限定为 2022-2026 年。
- 样板岗位采用三个窗口：2022-2023、2024-2025、2026。
- AI 智能体岗位可从 2023 年开始；若 2022 年没有真实岗位，不补造数据，而在演示中明确标注为“尚未形成稳定岗位样本”。
- `published_at` 缺失、仅有网页更新时间且不能证明发布日期、发布日期晚于采集时间或异常久远的记录进入待审区，不计入动态演化样本。

### 4.4 来源和地域配额

- 来源域不少于 8 个，冲刺目标为 10 个。
- 来源类型不少于 3 种，优先达到 4 种：授权平台、企业直供、企业官网、公共就业服务。
- 单一来源有效数据占比不高于 35%；超过 30% 时提前预警并暂停该来源的非缺口岗位导入。
- 地域分布遵循项目配置：一线、新一线、二线和其他城市均形成可分析样本，避免 90% 以上集中在北京、上海、广州、深圳。

## 5. 数据处理流程

### 5.1 授权预检

导入前验证授权方、文件名、文件哈希、数据范围、字段范围、允许用途、有效期、是否允许比赛展示和删除要求。授权材料与数据文件建立一一对应的清单。授权不完整时整批停止，不做部分猜测。

### 5.2 格式标准化

将 JSON、JSONL 和 CSV 映射为统一岗位结构。必须字段包括记录编号、岗位标题、公司、来源名称、来源地址或来源记录编号、采集时间和完整 JD 正文。地区、行业、经验、学历和薪资允许未知，但不得将薪资、职责段落等错误填入其他字段。

### 5.3 岗位重新分类

岗位分类只使用岗位标题与正文中的能力证据。`search_keyword`、文件目录名、采集员预填标签只能作为待验证提示，不能直接决定 `job_family_id`。

分类结果分为：

- `auto`：唯一岗位族同时具有足够标题和技能证据，自动进入后续质量门；
- `annotated`：原标签得到正文能力证据支持，保留标签并记录依据；
- `review`：证据不足、多个岗位族冲突或存在排除词，进入待审区；
- 自动分类与原标签不同但证据充分时，使用自动分类结果并保留原标签和变更原因。

### 5.4 日期可信度判定

优先使用来源明确提供的发布日期。只有“更新时间”时必须记录证据类型和置信度。无法证明年份的历史记录可以作为噪声治理样例，但不得计入 2022-2026 年有效数据和演化指标。

### 5.5 去重

依次执行：

1. 同一来源记录编号或规范化 URL 的精确重复；
2. 标准化正文内容哈希重复；
3. SimHash 或语义相似度识别跨平台抄袭和轻微改写；
4. 同公司、同岗位、相近日期的近重复复核。

重复记录保留来源关系和重复指向，但只选择一条主记录计入有效唯一总量。多个来源出现同一 JD 可作为“抄袭/转载”证据，不得重复计数。

### 5.6 质量门与入库

正式有效记录必须满足：

- 来源授权或公开访问状态已批准；
- 岗位标题、正文、公司、来源和采集时间存在；
- 正文达到最低有效长度且包含职责或任职要求；
- 岗位分类具有足够能力证据；
- 日期满足本轮分析范围或被明确标记为仅用于非时序分析；
- 不是重复记录；
- 字段没有明显错位；
- 保留原始载荷、文件哈希、处理规则版本和判定原因。

批次先执行 dry-run，生成暂存、待审、隔离和报告文件。只有报告、文件哈希、授权清单和质量指标全部通过，才允许确认提交。主库写入前必须生成可验证备份。

## 6. 组件边界

1. **授权清单校验器**：判断一个数据文件是否被允许处理，只依赖来源注册表和授权清单。
2. **格式适配器**：把不同导出格式转换为统一岗位记录，不决定岗位族和是否有效。
3. **岗位分类器**：基于标题和技能证据输出岗位族、置信度和原因，不负责数据库写入。
4. **质量门服务**：执行日期、字段、正文、来源和状态检查，输出有效、待审或隔离状态。
5. **重复治理器**：生成重复组和主记录关系，不删除原始数据。
6. **配额调度器**：根据岗位族、来源、地域和时间缺口生成下一批导入优先级。
7. **批次提交器**：验证报告和哈希、备份数据库并事务化提交，不绕过前述判定。
8. **覆盖率报告器**：输出总量、岗位族、来源、地域、年份、重复率、待审率和缺口。

这些组件通过统一记录结构和明确状态交互，任何组件都不能自行放宽其他组件的门槛。

## 7. 异常处理与恢复

- 文件编码、JSON 语法或列映射错误：整批停止并输出可定位的行号，不导入部分未知状态数据。
- 单条字段缺失或正文异常：进入隔离区，修复后以新批次重新导入，不直接修改数据库。
- 岗位分类冲突：进入待审区，保留候选岗位族和命中证据。
- 来源超过授权数量、路径或时间范围：整批停止并标记授权越界。
- 网络公开来源出现登录、验证码、访问拒绝或页面结构变化：立即停止该来源，不尝试绕过。
- 批次提交失败：数据库事务回滚，保留提交前备份、报告和错误日志。
- 同一文件重复运行：按文件哈希和记录指纹保持幂等，不增加岗位数量。

## 8. 测试与验证

### 8.1 单元与集成测试

- 授权范围、文件哈希和来源注册校验；
- 错误标签重分类，包括 Java 搜索结果中的嵌入式、前端和数据岗位；
- 2022-2026 日期边界、未知日期和未来日期；
- 精确重复、轻微改写和跨来源重复；
- 配额调度优先补齐零样本和低样本岗位族；
- dry-run 不写主库、确认提交生成备份、失败事务回滚；
- 幂等重跑不增加记录。

### 8.2 独立标注验证

从最终数据中分层抽取 300 条 JD，覆盖 22 个岗位族、各来源类型和三个时间窗口。双人独立标注岗位族、关键字段和核心技能；冲突由第三人仲裁。该集合在指标测试前冻结，不参与规则、词典或模型调优。

最低验收指标：

- JD 关键字段解析准确率 ≥90%；
- 岗位族分类宏平均 F1 ≥90%；
- 重复识别准确率和召回率均 ≥90%；
- 抽样来源授权与追溯完整率 100%；
- 单元测试覆盖率不低于比赛要求的 60%，项目内部目标不低于 70%。

## 9. 交付物

1. 最终有效岗位库及数据库备份；
2. 原始授权文件清单、文件哈希和授权证明索引；
3. 每批 dry-run、待审、隔离、提交和修复报告；
4. 最终覆盖率报告和岗位族缺口报告；
5. 300 条冻结双人标注测试集及标注规范；
6. 数据质量与算法指标报告；
7. 演示用 AI 智能体和 Java 岗位输入、输出及证据样例；
8. 可复现的导入、重建、验收和回滚操作记录。

## 10. 验收条件

方案 A 在同时满足以下条件时视为完成：

- 有效唯一 JD ≥5,000，冲刺目标 5,400；
- 22 个岗位族全部 ≥100 条；
- AI 智能体和 Java 各 ≥500 条；
- 来源域 ≥8、来源类型 ≥3、单一来源占比 ≤35%；
- 有效动态演化记录位于 2022-2026 年并具有可信日期证据；
- 300 条独立测试集冻结且三项数据质量指标达到约定门槛；
- 所有正式数据均可追溯到授权清单或已批准公开来源；
- 全流程可幂等重跑、可审计、可备份和可回滚；
- 不以伪造、重复计数、修改发布日期或降低质量门的方式补数量。

## 11. 风险与控制

- **新增授权文件不足**：要达到最终 5,000 条，当前至少缺少 4,454 条可信时序记录；优先扩大合作企业直供和已批准企业官网来源，不转向未授权商业平台抓取。
- **平台导出误检率过高**：按岗位族细化导出条件，并根据每批合格率停止低收益来源。
- **稀缺岗位难以达到 100 条**：扩大标题别名和行业覆盖，但仍要求正文技能证据；若真实市场样本不足，报告真实缺口，不伪造岗位。
- **单一来源再次过高**：在 30% 时预警，35% 时阻止该来源的非缺口岗位继续计入有效总量。
- **数量目标与准确率冲突**：准确率、授权和追溯优先于数量，低质量记录保留为噪声案例而不计入有效总量。
