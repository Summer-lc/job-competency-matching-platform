# 全国大型招聘平台授权采集设计

## 目标

在现有岗位知识库基础上，接入 BOSS直聘、前程无忧、猎聘、拉勾招聘以及全国公共就业平台的已授权岗位数据。正式库最终保留 5000 至 10000 条门禁通过且跨平台去重后的可用唯一岗位，并支持后续增量更新、知识图谱同步和真实时间演化分析。

## 授权边界

- 商业平台范围：BOSS直聘、前程无忧、猎聘、拉勾招聘。
- 全国公共平台范围：国家大学生就业服务平台、中国公共招聘网、中国国家人才网、就业在线等全国性公共就业平台。
- 商业平台仅允许使用平台书面授权所覆盖的 API、批量导出文件或其他明确许可的数据通道。
- 每个来源必须登记授权编号、有效期、允许的数据范围、允许的访问方式和允许的请求频率。
- 授权令牌和账号凭据只从环境变量或本机密钥配置读取，不写入源码、数据库、JSONL、日志或采集报告。
- 不绕过登录、验证码、签名、访问控制、请求频率限制或其他技术措施。实际接口超出授权范围时，采集器立即停止该来源。
- 平台授权原件不写入岗位记录。岗位记录仅保留可审计的 `authorization_reference`。

## 方案选择

采用“官方接口或平台授权导出优先”的方案：每个平台拥有独立适配器，统一输出项目现有的规范岗位记录。无公开或授权 API 时，使用平台提供的批量导出文件；只有在授权明确包含浏览器自动化时才允许使用该方式。

不采用省级公共招聘网站补量，也不使用国外招聘网站、第三方转售数据、非授权爬虫工具或规避反爬机制的数据。

## 来源配额

以下数量是门禁通过且跨平台去重后的新增可用目标，不是原始抓取量：

| 来源 | 可用目标 |
| --- | ---: |
| BOSS直聘 | 1500 |
| 前程无忧 | 1000 |
| 猎聘 | 800 |
| 拉勾招聘 | 700 |
| 国家大学生就业服务平台 | 500 |
| 中国公共招聘网 | 500 |
| 中国国家人才网或就业在线 | 400 |
| 当前已入库有效岗位 | 1297 |

原始采集量预计为 7000 至 8000 条。采集服务按门禁后的有效数量判断是否完成；达到 5000 条原始记录不视为完成。某个平台不可用时，只能在已登记、已授权的全国性来源之间调整配额，并继续满足来源多样性限制。

## 覆盖策略

采集矩阵由“岗位族 × 城市层级 × 平台 × 时间窗口”组成：

- 覆盖项目定义的 22 个岗位族。
- 强制补齐当前缺失的 `AI_SOLUTION_ENGINEER`、`MLOPS_ENGINEER`、`MULTIMODAL_ENGINEER` 和 `PROMPT_ENGINEER`。
- 城市覆盖一线、新一线、二线及其他城市，不按省级平台或单一地域集中采样。
- 每个平台按岗位族和城市层级设置批次上限，防止 Java、前端或少数热门城市挤占样本。
- 优先采集具有可信发布时间、完整岗位描述、明确工作地点和企业名称的岗位。
- 保留首次发现时间、最后发现时间、平台更新时间和岗位有效状态，用于季度演化分析。

## 统一记录格式

各适配器输出 UTF-8 JSONL。每行是一个独立 JSON 对象，至少包含：

```json
{
  "source_id": "boss_zhipin_authorized",
  "source_job_id": "平台岗位唯一编号",
  "title": "岗位名称",
  "company": "公司名称",
  "city": "城市",
  "district": "区县",
  "salary_min": 15000,
  "salary_max": 25000,
  "salary_months": 12,
  "education": "本科",
  "experience": "3-5年",
  "description": "岗位职责与任职要求",
  "published_at": "2026-08-12T10:00:00+08:00",
  "source_url": "原始岗位页面",
  "collected_at": "2026-08-12T18:00:00+08:00",
  "job_family": "JAVA_DEVELOPER",
  "authorization_reference": "授权文件或接口编号"
}
```

适配器可以在 `adapter_extra` 中保留平台特有的非敏感字段，但不能改变统一字段含义。缺失值使用 `null`，不得以空字符串、`未知` 或推测值替代。

## 组件设计

### 来源注册表

扩展 `config/job_sources.json`，为每个来源登记：

- 国内市场范围和来源类型。
- 固定域名与允许路径。
- `authorized_api` 或 `authorized_file_export` 采集模式。
- 授权引用、有效期和授权范围摘要。
- 请求频率、分页上限、记录上限和解析器版本。
- 启用状态和最近一次人工复核日期。

来源注册表继续采用失败关闭策略。授权缺失、过期、域名不匹配或采集模式不匹配时不得运行。

### 平台适配器

为 BOSS直聘、前程无忧、猎聘、拉勾招聘分别建立小型适配器。适配器只负责：

- 构造授权范围内的列表和详情请求，或读取平台授权导出文件。
- 解析平台字段并输出统一记录。
- 保留平台岗位编号、原始网址、发布时间和采集证据。
- 对结构变化、授权失败、限流和不完整详情给出明确错误。

全国公共平台沿用现有适配器边界；中国公共招聘网当前接口恢复并通过预检前保持停用。就业在线的加密接口不得逆向或绕过，只能在获得正式接口文档与凭据后接入。

### 配额调度器

调度器读取岗位族查询配置和来源配额，按缺口生成批次。每个批次包含来源、岗位族、城市层级、时间窗口和最大记录数。调度器优先补齐缺失岗位族，并依据门禁结果动态调整后续批次，而不是按原始返回量提前结束。

### 统一质量门禁

所有来源复用现有门禁、暂存、审计和导入流水线，并增加：

- 授权引用存在且有效。
- 来源域名与注册表一致。
- 发布时间和采集时间可解析。
- 招聘联系人、手机号、邮箱、即时通信账号等个人信息已删除。
- 岗位描述、公司、地点和发布时间满足完整性要求。
- 岗位族分类达到正式入库置信度，否则进入人工复核。

### 去重与版本更新

同平台优先使用 `source_id + source_job_id` 幂等更新。跨平台使用规范化岗位名称、企业名称、城市、描述指纹和相近发布时间进行聚类去重。跨平台重复记录保留一条主记录，同时保存来源证据集合，避免为了增加来源数量重复计算同一岗位。

增量采集不会覆盖首次发现时间。再次出现的岗位更新最后发现时间和字段版本；连续多个采集周期未出现的岗位标记为可能失效，不物理删除历史记录。

## 数据流程

1. 校验来源注册、授权有效期、凭据存在性和调用模式。
2. 生成岗位族、城市层级和时间窗口批次。
3. 每个平台先采集 10 至 20 条进行结构预检。
4. 解析为统一记录并生成原始响应快照哈希。
5. 执行脱敏、字段校验、岗位族分类和质量门禁。
6. 执行同平台幂等和跨平台聚类去重。
7. 生成预检报告；只有正式提交命令才能写入数据库。
8. 写入前创建数据库备份并保留运行审计。
9. 导入完成后重建知识库、知识图谱、季度画像和演化事件。
10. 输出数量、覆盖、质量、来源分布和失败来源验收报告。

## 错误处理

- 单一来源失败不影响其他来源批次。
- 授权失败、域名越界、验证码、签名异常或访问控制变化立即停止该来源。
- 连续结构解析失败触发熔断并保存最小诊断信息，不反复请求目标平台。
- HTTP 429 或平台限流响应按授权规则退避；超过本批次重试上限后停止，不更换代理规避限制。
- 原始响应不得包含在普通日志中；诊断快照采用访问受限目录并记录哈希。
- 任一批次提交失败时不生成部分正式导入，保证数据库事务一致性。

## 验收标准

- 正式库拥有 5000 至 10000 条门禁通过且跨平台去重后的可用唯一岗位。
- 22 个目标岗位族全部覆盖。
- 至少 8 个独立来源域名和 3 类来源。
- 任一来源占可用唯一岗位的比例不超过 35%。
- 岗位描述、公司、地点和可信发布时间完整率均不低于 90%。
- 每条正式岗位具有来源、采集时间和授权引用。
- 国外岗位、重复岗位、失效岗位和个人敏感信息不进入正式有效集合。
- 重复运行同一批次不会生成重复岗位、重复审计或重复知识图谱实体。
- 数据库、知识库、知识图谱和验收统计在同一流水线运行后保持一致。

## 测试范围

- 每个平台列表、详情或导出格式的固定样例解析测试。
- 来源授权、有效期、域名、路径和采集模式的失败关闭测试。
- 凭据不落盘和日志不泄漏测试。
- 手机号、邮箱、联系人和即时通信账号脱敏测试。
- 同平台幂等与跨平台重复岗位测试。
- 岗位族分类、缺失岗位族优先级和城市层级配额测试。
- 限流、授权失效、页面结构变化、部分字段缺失和断点续采测试。
- 预检、正式提交、数据库备份、知识图谱同步和验收统计端到端测试。

## 非目标

- 不采集个人简历、求职者联系方式或平台聊天数据。
- 不开发验证码识别、代理池、账号轮换、签名逆向或反爬绕过能力。
- 不用合成岗位或重复岗位凑足验收数量。
- 本阶段不改变现有系统界面；只扩展采集、质量和持续更新能力。
