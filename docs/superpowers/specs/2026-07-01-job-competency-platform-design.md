# 岗位能力图谱与动态演化平台设计

## 目标

将现有教育场景的 LangChain + DeepSeek 项目改造成符合 XH-202621 赛题要求的岗位能力动态演化与人岗匹配系统，形成“数据导入与治理 -> 新岗位发现和既有岗位更新 -> 技能级图谱 -> 简历解析 -> 匹配诊断与学习路径 -> 人工审核”的闭环。

## 保留能力

- DeepSeek/OpenAI 兼容模型调用与模型选择。
- PDF、DOCX、Markdown 文档解析。
- FAISS、BM25、混合检索与重排序能力。
- Neo4j 图存储基础封装。
- 通用知识图谱结构和 RAG 证据检索思路。

## 删除范围

- 学生、教师、班级、花名册、作业、批改、测验、错题本、BKT 掌握度和学习监测模块。
- 机器学习教材、课程知识库、学校品牌图片、论文/PPT 生成脚本和历史教育场景文档。
- 已生成缓存、输出、临时文件、旧迁移脚本和无项目清单支撑的 `node_modules`。
- 旧版教育前端和管理员页面。

## 业务架构

1. 数据治理：导入 JSONL/CSV，校验字段，标准化岗位名称，计算内容哈希和 SimHash，标记重复、来源可信度和质量分。
2. 岗位抽取：从 JD 提取职责、必备技能、加分技能、经验和学历要求；保存原始证据片段。
3. 岗位分析：根据时间窗口、增长率、跨来源覆盖和技能组合新颖度识别新岗位；对既有岗位输出能力新增、删除和修改。
4. 知识图谱：展示岗位、技能、职责、行业、等级、版本和来源证据，支持按技术栈和级别筛选。
5. 简历解析：解析 PDF/DOCX/TXT，提取技能、项目、经验和教育信息，所有结果保留证据文本。
6. 人岗匹配：按必备技能、熟练度/经验、技能时效、项目行业证据和加分技能评分，输出缺口、建议和学习路径。
7. 人工审核：低置信岗位、技能和演化结果进入审核队列，支持通过、驳回和修改。
8. 评测：提供 JD 解析、简历提取、匹配准确率和测试覆盖率入口。

## 数据与接口

默认使用 SQLAlchemy + SQLite，允许通过 `DATABASE_URL` 切换 MySQL。Neo4j 为可选图存储，未配置时系统仍可通过关系型数据库完成演示。

核心接口：

- `POST /api/data/import`：导入 JSONL/CSV JD 数据。
- `GET /api/data/stats`：数据质量与来源统计。
- `GET /api/jobs`、`GET /api/jobs/{id}`：岗位列表与详情。
- `POST /api/analysis/rebuild`：重建岗位画像、演化和候选新岗位。
- `GET /api/analysis/emerging`：候选新岗位。
- `GET /api/analysis/evolution/{job_family}`：岗位能力演化。
- `GET /api/graph`：技能级全景图谱。
- `POST /api/resumes/parse`：解析简历。
- `POST /api/matches`：匹配与差距诊断。
- `GET /api/reviews`、`POST /api/reviews/{id}/decision`：人工审核。
- `GET /api/evaluation/summary`：指标摘要。

## 前端

单页前端包含总览、数据治理、岗位发现、能力演化、全景图谱、人岗匹配和人工审核。首页直接展示数据规模、来源数、岗位数、技能数、候选新岗位数和待审核数。演示主线可在 10 分钟内完成。

## 幻觉防控

- 结构化输出进行字段校验。
- 技能和岗位结论必须关联 JD 或官方证据。
- 采用跨来源支持数、来源可信度、时间衰减和抽取置信度形成综合置信度。
- 低置信结果不进入正式图谱，仅进入审核队列。
- 生成式建议明确区分“证据结论”和“模型建议”。

## 测试

- 数据格式、去重、技能抽取和质量评分单元测试。
- 新岗位发现、岗位演化和图谱筛选测试。
- PDF/DOCX 文本解析、技能证据和匹配评分测试。
- API 集成测试和前端关键流程验证。
- 最终覆盖率目标不低于 60%，三项业务准确率评测接口目标不低于 90%。
