# 产品化界面与使用说明设计

## 目标

将系统界面从比赛展示口径调整为面向实际用户的产品表达。保留数据治理、岗位发现、能力演化、知识图谱、人岗匹配、人工审核和自动评测能力，不在界面直接展示比赛编号、赛题名称、参赛状态或比赛验收门槛。

## 修改范围

### 界面文案

- 删除侧栏中的 `XH-202621`，替换为“多源岗位智能分析”。
- 将“比赛核心闭环”改为“核心业务闭环”，删除“现场演示”等比赛语境。
- 将“指标评测”改为“模型质量评测”。
- 将“参赛就绪状态”改为“质量评测状态”。
- 删除界面中的“赛题要求”“参赛就绪”“最终参赛就绪”等表达。
- 不展示至少 100 条 JD、准确率不低于 90%、测试覆盖率不低于 60% 等具体比赛门槛。
- 评测卡片保留真实计算结果，目标提示统一改为“基于标注集自动计算”或“自动化测试保障”。

### 保留功能

- 保留评测数据上传、自动计算 Precision、Recall、F1、Accuracy 和失败案例的能力。
- 保留后端目标配置和质量判断逻辑，避免破坏现有验收与自动测试；这些内部阈值不直接显示在产品界面。
- 保留全部业务页面、接口和数据库结构。
- 将 FastAPI 描述改为通用的岗位能力图谱平台描述。

### 使用说明

新增 `USER_GUIDE.md`，按照实际操作顺序说明：

1. 启动与访问系统。
2. 导入岗位数据并查看隔离、重复和审核结果。
3. 查看岗位发现与能力演化。
4. 使用全景图谱的岗位族、版本、节点类型、技术栈、级别和证据筛选。
5. 上传简历并查看匹配分数、能力差距和学习路径。
6. 处理人工审核项目。
7. 上传标注集运行模型质量评测。
8. 使用命令行持续导入后续数据。

## 产品亮点表达

界面和使用说明重点突出以下能力：

- 增量更新：文件指纹、记录修订和岗位族局部重建。
- 可信治理：异常隔离、重复识别、低质量审核和原始数据留存。
- 证据追溯：技能、职责和场景均可回到原始 JD 文本与来源链接。
- 动态演化：岗位画像版本化，记录技能、职责和场景的新增、删除与变化。
- 全景图谱：支持岗位、技能、职责、场景和证据多类节点联动筛选。
- 可解释匹配：给出技能级匹配、能力缺口和学习建议，而不是只有总分。
- 自动评测：通过人工标注集客观计算质量指标并保留失败样本。

## 测试与验收

- 增加静态界面测试，确保页面不再出现比赛编号、比赛、赛题、参赛就绪及具体比赛门槛。
- 保留并运行现有评测 API 测试，确认上传、计算、保存和展示功能不受影响。
- 运行完整测试套件并保持核心覆盖率门槛。
- 启动本地系统，在浏览器中检查首页和模型质量评测页面，确认页面无控制台错误。

## 非目标

- 不删除自动评测服务或数据库记录。
- 不修改比赛研究文档、内部设计文档和测试目标配置。
- 不增加比赛模式与产品模式开关。
- 不改变知识库、图谱和匹配算法。
