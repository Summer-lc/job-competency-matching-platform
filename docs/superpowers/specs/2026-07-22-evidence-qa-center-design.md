# 证据知识问答中心设计

## 目标

在现有岗位知识库、JD 原文证据和 DeepSeek 能力之上新增“知识问答”页面。用户可以按岗位族提出问题，系统先检索真实证据，再生成带证据编号的回答；模型不可用时返回可追溯的提取式摘要，证据不足时拒绝生成。

## 方案选择

采用“证据检索 + 单轮智能问答 + 无模型降级”方案。首期不保存多轮聊天历史，不允许模型使用检索证据之外的通用知识。该方案兼顾可展示性、可复现性和幻觉控制，也能在模型服务暂时不可用时保持核心功能可用。

## 页面设计

新增“知识问答”导航页，放在“全景图谱”之后。页面包含：

- 问题输入框；
- 岗位族筛选；
- 检索证据数量选择；
- 推荐问题快捷按钮；
- “检索证据”和“生成证据回答”操作；
- 回答卡片，展示实际回答模式、引用编号和状态；
- 证据列表，展示编号、证据类型、岗位/标题、企业或发布方、相关度、原文片段、来源链接；
- 无结果、证据不足、模型降级和请求失败的明确提示。

导航顺序调整为：系统总览、数据治理、岗位发现、能力演化、全景图谱、知识问答、人岗匹配、人工审核、模型质量评测。

## 证据范围与优先级

问答证据由两部分组成：

1. `KnowledgeChunk`：从有效或待审核 JD 中生成的岗位、技能和职责知识片段，保留岗位编号、岗位族、企业、来源名称和来源链接。
2. `EvidenceRecord`：职业标准、官方技术文档和行业趋势等外部证据，保留发布方、证据类型、时间和来源可信度。

检索排序综合词法相关度与来源权重。同等相关度下，官方标准和官方技术文档优先于行业报告，行业报告优先于企业 JD。岗位族筛选必须同时作用于两类证据。待审核 JD 可以参与草稿回答，但在证据卡片中显示审核状态。

每次回答最多使用用户指定的 3 至 12 条证据。统一编号为 `[K1]`、`[K2]`，编号只在本次响应内有效，并与返回的证据数组一一对应。

## 后端组件

新增 `src/evidence_qa_service.py`，负责以下边界清晰的能力：

- `gather_answer_evidence()`：检索 JD 知识片段和外部证据，归一化字段、排序、去重和编号；
- `build_grounded_prompt()`：生成只允许引用给定证据的提示词；
- `build_extractive_answer()`：模型不可用时，根据高相关证据生成确定性摘要；
- `answer_knowledge_question()`：编排检索、模型调用、引用校验和降级。

新增 `POST /api/knowledge/answer`。请求字段：

```json
{
  "question": "数据工程师需要掌握哪些实时计算技能？",
  "family_code": "DATA_ENGINEER",
  "limit": 6,
  "model": "deepseek-v4-pro"
}
```

响应字段：

```json
{
  "answer": "……[K1]……[K2]",
  "mode": "grounded_llm",
  "family_code": "DATA_ENGINEER",
  "citations_valid": true,
  "evidence": [],
  "warning": null
}
```

`mode` 只能是 `grounded_llm` 或 `extractive_fallback`。保留现有 `GET /api/knowledge/search` 和 `POST /api/assistant/explain`，不破坏已有调用。

## 回答约束

提示词要求模型：

- 只能依据编号证据回答；
- 每个主要结论都必须引用至少一个编号；
- 不得引用响应中不存在的编号；
- 证据冲突时明确指出来源差异；
- 证据不足时直接说明不足，不补充常识猜测；
- 使用简洁中文回答。

模型返回后执行引用校验。若包含不存在的编号、完全没有引用或回答为空，则丢弃模型结果并返回提取式摘要。系统不会把不合格的模型回答直接展示给用户。

## 降级与错误处理

- 未检索到证据：返回 HTTP 422，说明当前知识库没有足够证据。
- DeepSeek 未配置、超时或调用失败：返回 `extractive_fallback`，同时提供简短提示，不返回 503。
- 模型引用不合法：返回 `extractive_fallback`，并将警告标记为“模型回答未通过引用校验”。
- 外部证据为零：继续使用 JD 知识片段回答，页面不显示虚假的跨来源状态。
- 来源链接缺失：证据仍可展示，但不渲染跳转按钮。

## 数据流

```text
用户问题与岗位族
  -> JD 知识片段词法检索
  -> 外部证据相关度检索
  -> 来源加权、去重与统一编号
  -> 证据为空则拒绝
  -> DeepSeek 证据约束回答
  -> 引用编号校验
  -> 合格回答或提取式降级
  -> 回答与证据卡片同时展示
```

## 测试与验收

- 服务测试：两类证据合并、岗位族过滤、来源优先级、去重和稳定编号。
- 回答测试：合法引用通过、无引用和越界引用触发降级、模型异常触发降级、无证据返回 422。
- API 测试：请求校验、响应模式、证据字段和旧接口兼容。
- 前端静态测试：知识问答导航、问题输入、证据列表和新接口地址存在。
- 浏览器测试：推荐问题、检索、回答、来源链接和错误提示可用，控制台无错误。
- 完整回归测试继续保持项目覆盖率门槛。

## 非目标

- 不保存聊天历史或用户画像。
- 不实现模型自由联网搜索。
- 不让模型直接修改知识库或图谱。
- 不新增向量数据库依赖；继续使用现有词法检索和可插拔向量接口。
- 不改变现有岗位画像、能力演化和人岗匹配算法。
