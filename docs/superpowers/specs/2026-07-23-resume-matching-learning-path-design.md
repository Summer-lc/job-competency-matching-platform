# 人岗匹配效果优化设计

**日期：** 2026-07-23  
**范围：** 简历解析、单岗位匹配、Top 5 岗位推荐、个性化学习路径、自动评测

## 1. 目标与边界

本次改造将现有基于技能名称精确交集的匹配流程升级为证据优先、可复现、可降级的混合匹配系统。系统从简历中形成结构化能力档案，对单个岗位给出七维诊断，同时从有效岗位画像中推荐最匹配的五个岗位，并根据能力缺口生成可验证的30/60/90天学习路径。

本阶段保留现有岗位画像、知识图谱、简历记录和匹配记录，不删除历史数据。DeepSeek只用于补充结构化信息和生成受证据约束的解释，不直接决定最终匹配分数。姓名、性别、年龄、籍贯等非能力信息不得参与评分。

## 2. 总体架构

```text
简历文件
  -> 文本提取与章节切分
  -> 规则能力解析
  -> DeepSeek证据约束补充（可选）
  -> 能力规范化与证据校验
  -> 结构化简历能力档案
  -> 候选岗位召回
  -> 七维证据评分
  -> 单岗位诊断 / Top 5推荐
  -> 能力差距排序
  -> 30/60/90天学习路径
```

核心组件：

1. `ResumeParser`：章节识别、时间线、技能、项目、教育和证据提取。
2. `ResumeEnrichmentService`：调用DeepSeek补充规则未覆盖的信息并校验证据。
3. `SkillNormalizer`：技能别名、规范名称、相邻技能和前置关系映射。
4. `MatchingEngine`：七维可复现评分、等级限制和置信度计算。
5. `JobRecommendationService`：候选召回、画像过滤、岗位族去重和Top 5排序。
6. `LearningPathService`：按依赖和缺口生成分阶段、可验收的学习计划。

## 3. 结构化简历能力档案

### 3.1 文本与章节

继续支持PDF、DOCX、TXT和Markdown。解析器识别基本信息、专业技能、工作经历、项目经历、教育经历和证书等章节，并保留每个结构化字段对应的原文证据。PDF或DOCX无法提取有效文本时返回明确错误，不生成空能力档案。

### 3.2 工作时间线

每段工作经历包含企业、岗位、起止时间、持续月数、职责、技能和原文证据。总经验年限按工作区间合并计算，重叠任职月份只计一次；无法识别日期时，才使用“X年工作经验”等明确表述作为回退值。教育年限、项目周期和年龄不得被识别为工作年限。

### 3.3 技能能力项

每项技能包含：

- `name`：知识图谱中的规范技能名称。
- `aliases`：简历中出现的原始别名。
- `category`：语言、框架、数据库、云原生等类别。
- `proficiency`：`aware`、`working`、`advanced`、`expert`。
- `last_used_at`：最近一次有时间证据的使用日期。
- `evidence_sources`：`skill_section`、`work`、`project`、`certificate`。
- `evidence`：原文片段、章节、起止位置和可信度。
- `confidence`：规则、模型和证据一致性共同形成的置信度。

项目或工作经历中的实际使用证据高于技能清单中的自我陈述。否定语句、学习计划和岗位描述引用不得作为候选人已掌握技能的证据。

### 3.4 项目经历

项目包含名称、角色、起止时间、技术栈、职责、量化成果、行业场景和证据。量化成果必须来自简历原文中的数字、比例、规模或明确结果；模型不得补写不存在的成果。

### 3.5 DeepSeek补充与降级

规则解析先执行。DeepSeek只接收原始章节和规则解析结果，返回严格JSON，补充隐含技能、角色、成果和时间关系。每个新增字段必须引用输入中的连续原文片段；引用不存在、结构错误或置信度不足的字段被丢弃。模型超时或不可用时直接返回规则结果，并将`parser_mode`标记为`rules`；成功补充时标记为`hybrid`。

## 4. 技能规范化与关系

技能规范化复用岗位数据的技能目录，并扩展常见中英文别名、缩写和版本表达，例如`K8s -> Kubernetes`、`SpringBoot -> Spring Boot`。匹配关系分为：

- `exact`：同一规范技能，获得完整技能分。
- `related`：可迁移的相邻技能，只获得部分分数并明确显示为迁移能力。
- `prerequisite`：目标技能的前置技能，用于学习路径，不视为目标技能已满足。

关系表使用确定性配置和知识图谱数据，不允许由大模型临时创造关系。所有规范化结果保留原始名称，便于追溯。

## 5. 候选岗位召回与Top 5推荐

候选来源优先使用活跃季度画像；当岗位族没有可用季度画像时，可回退到最新非废弃画像并显示画像类型和置信提示。被拒绝、已废弃或没有技能要求的画像不进入推荐。

第一阶段按规范技能重合、相邻技能、岗位层级和行业场景形成候选集合。第二阶段调用七维评分。最终按总分、结果置信度、画像证据量和岗位名称稳定排序，并按岗位族去重，每个岗位族最多保留一个最优层级画像，返回Top 5。

推荐结果包含画像编号、岗位族、岗位名称、层级、季度、总分、匹配等级、置信度、主要优势、主要缺口和画像样本状态。

## 6. 七维证据评分

总分固定为100分：

| 维度 | 满分 | 核心口径 |
| --- | ---: | --- |
| 必备技能覆盖 | 30 | 精确技能完整计分，相邻技能只计迁移分 |
| 技能熟练度 | 15 | 比较简历证据熟练度与岗位要求熟练度 |
| 工作经验与岗位层级 | 15 | 比较有效经验年限、职责跨度和画像层级 |
| 项目证据 | 15 | 按必备技能的项目覆盖、角色和成果计分 |
| 技能时效 | 10 | 最近两年使用得分最高，无日期证据降低置信度 |
| 加分技能 | 5 | 计算岗位加分技能覆盖 |
| 职责与行业场景 | 10 | 匹配职责关键词、项目场景和行业经验 |

每个维度返回`score`、`max_score`、`ratio`、`evidence`、`gaps`和`explanation`。最终分数使用固定公式计算，DeepSeek生成的文字不得改写分值。

### 6.1 防虚高规则

- 缺失高普及率的核心必备技能时，总分最高为79分。
- 必备技能覆盖低于50%时，总分最高为59分。
- 没有任何工作或项目证据时，项目证据维度为0，结果置信度不得高于`medium`。
- 经验与目标层级明显不匹配时扣除对应维度分，但不使用年龄推断经验。
- 相邻技能最多获得该技能完整分的40%，且仍列入待补齐项。

匹配等级保持兼容：`high >= 80`、`medium >= 60`、`low < 60`。同时返回`confidence`和`confidence_reasons`，将“匹配程度”与“证据是否充分”分开表达。

## 7. 个性化学习路径

学习路径只针对未满足或熟练度不足的岗位能力生成。排序依据为：核心必备技能、技能依赖、岗位普及率、预计提分、候选人已有迁移能力和项目组合效率。

### 7.1 阶段结构

- 0-30天，基础补齐：学习核心技能的前置知识并完成小型验证任务。
- 31-60天，岗位能力：完成目标岗位必备技能训练，并达到岗位要求熟练度。
- 61-90天，项目验证：完成贴近岗位职责和行业场景的综合项目，形成可验证成果。
- 简历强化：将已完成成果整理为真实、量化、可追问的简历证据，不生成虚构经历。

### 7.2 学习节点

每个节点包含技能目标、优先级、推荐顺序、原因、可复用能力、前置技能、学习任务、实战项目、完成标准、预计分数提升和岗位证据。预计分数提升是基于当前固定评分公式的上限估计，所有节点提升合计不得使预计总分超过100。

系统不编造课程链接。只有知识库中存在可信职业标准、官方技术文档或外部证据时，节点才附带来源标题和URL。

## 8. 数据持久化与兼容

现有`ResumeRecord.parsed_json`保存新版能力档案，增加`schema_version`和`parser_mode`。旧记录在读取时经过兼容适配，不强制重写原始数据。

现有`MatchRecord`继续保存总分、维度分、缺口和建议。新版JSON增加维度证据、置信度、匹配等级、评分版本和学习路径版本。历史记录保持可读，不参与新版算法准确率证明。

每次Top 5推荐均使用新的推荐运行及推荐结果表保存，记录简历、评分版本、候选画像、排名、分数和生成时间，确保推荐可复现和可审计。相同简历、相同候选画像状态和相同评分版本重复推荐时复用同一结果签名，不重复创建相同推荐结果。

## 9. API与界面

保留：

- `POST /api/resumes/parse`：返回新版能力档案。
- `POST /api/matches`：对指定岗位生成深度匹配诊断。

新增：

- `POST /api/matches/recommend`：输入`resume_id`和可选岗位层级、岗位族筛选条件，保存并返回按岗位族去重的Top 5岗位。
- `GET /api/matches/{match_id}`：读取已保存的完整诊断证据和学习路径。

人岗匹配页面依次展示简历能力档案、Top 5岗位推荐和选中岗位的深度诊断。深度诊断展示七维评分、正负向因素、证据明细、能力缺口和30/60/90天路径。低样本岗位、规则降级解析和低置信结果均显示中性提示。界面不展示赛项编号、奖项目标或规则原文。

## 10. 错误处理

- 文件类型不支持或文本为空：返回400，不写入简历记录。
- DeepSeek不可用：保留规则解析结果，不中断流程。
- 模型证据无效：丢弃对应补充字段并记录原因。
- 简历或岗位不存在：返回404。
- 没有可推荐画像：返回空列表和明确原因，不返回伪造候选。
- 岗位画像缺少技能或样本不足：降低结果置信度并显示数据缺口。
- 推荐或匹配保存失败：事务回滚，不留下半条运行记录。

## 11. 自动评测

### 11.1 简历解析

保留技能Precision、Recall、F1及整条Accuracy，继续验证经验年限和学历；新增工作时间线、项目技能、量化成果和证据片段有效性测试。规则模式和混合模式分别记录指标，避免模型结果掩盖基础解析能力。

### 11.2 单岗位匹配

保留`high`、`medium`、`low`分类评测，并增加核心技能缺失、同义技能、相邻技能、经验不足、无项目证据和层级错配案例。评分必须具备确定性，同一输入重复运行结果一致。

### 11.3 岗位推荐

新增Top-1 Accuracy、Recall@5、MRR和NDCG@5。人工标注数据为每份简历提供相关岗位族及相关性等级。评测集与技能别名、权重和阈值调优数据隔离。

## 12. 验收标准

- PDF、DOCX、TXT和Markdown解析兼容原接口。
- 简历能力项、工作经历和项目经历均可追溯到原文证据。
- 工作年限按时间线去重计算，教育年限不计入工作经验。
- DeepSeek失败时规则模式仍可完成解析、匹配和推荐。
- 七维分数之和等于总分，防虚高规则稳定生效。
- Top 5按岗位族去重，排序稳定且每项包含原因和置信度。
- 学习路径遵循前置关系，包含可验证任务和预计提分，不生成虚构经历或链接。
- 旧简历、旧匹配记录和现有评测接口继续可用。
- 新增行为均经过测试先失败、实现后通过的测试驱动流程。
- 完整自动化测试通过，覆盖率不低于现有门槛。
