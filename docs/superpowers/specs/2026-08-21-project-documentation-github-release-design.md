# 项目文档与 GitHub 交付设计

## 目标

为两位尚未全面参与项目的组员提供一套可独立阅读、可用于整理 PPT 和技术文档的项目资料，并将经过脱敏、可复现的工程内容发布到新的私有 GitHub 仓库 `job-competency-matching-platform`。

## 读者与使用场景

- 首要读者：需要快速了解项目现状、架构、运行流程和技术方案的组内成员。
- 主要用途：制作项目汇报 PPT、撰写技术文档、复现系统、继续开发和准备答辩。
- 阅读目标：读者无需先通读全部源码，即可回答项目做了什么、完成到哪一步、如何运行、输入输出是什么、采用哪些模型与算法、当前结果是否达标，以及哪些文件可以安全上传。

## 仓库方案

采用新的私有仓库，不修改现有 `intelligent-employment-assistant` 仓库。

- 仓库名称：`job-competency-matching-platform`
- 默认分支：`main`
- 发布内容：业务源码、测试、前端页面、配置模板、Docker 文件、示例数据、项目说明、技术文档和经筛选的演示材料。
- 排除内容：真实 `.env`、API 密钥、主数据库及其备份、原始批量采集数据、运行缓存、临时测试目录、覆盖率缓存和其他不必要的大文件。

## 文档结构

### 1. 根目录 README

作为项目入口，包含：

- 项目定位与核心价值；
- 当前完成情况和关键数字；
- 系统架构与端到端数据流；
- 快速启动与演示入口；
- 文档导航；
- 已知限制和后续工作。

### 2. 项目总览文档

集中说明：

- 项目背景、目标和范围；
- 已完成、部分完成、尚未完成的功能；
- 当前数据库和测试结果；
- PPT 推荐叙事主线与可复用素材索引。

### 3. 技术架构与运行流程文档

包含：

- 模块边界；
- 数据层、服务层、接口层和前端之间的关系；
- 岗位导入、治理、画像、演化、知识问答、简历解析、匹配推荐和评测的调用流程；
- 关键代码入口与文件职责；
- SQLite、可选 Neo4j 和外部模型服务的依赖关系。

### 4. 输入输出与算法文档

包含：

- JD、证据、简历和评测集的输入格式；
- 主要 API 和命令行输入输出；
- SHA-256、SimHash、质量评分、规则抽取、技能标准化、季度画像、演化判断、词法/向量检索、七维匹配、Top 5 推荐和评测指标；
- DeepSeek 的调用位置、默认降级逻辑和当前不存在本地模型权重文件的事实。

### 5. 环境与部署文档

包含：

- Python 3.11 环境；
- 依赖安装；
- `.env.example` 字段说明；
- 本地启动、Docker Compose、可选 Neo4j；
- 测试与覆盖率门禁；
- 常见问题和数据初始化方式。

### 6. 文件清单与 GitHub 发布说明

列出：

- 主要代码文件及职责；
- 配置、示例、测试和演示材料；
- 被排除文件及原因；
- 大文件、敏感数据和许可证风险提示。

## 当前事实基线

文档以 2026 年 8 月 21 日的本地检查结果为准：

- 完整测试：1,021 项通过，6 项跳过；
- 代码覆盖率：87.21%，通过 60% 门禁；
- 主数据库：2,568 条岗位记录、18 个岗位族、49 个技能、70 个岗位画像、492 个演化事件、2,077 个知识片段；
- 最近一次验收快照：1,318 条可用唯一岗位，距离 5,000 条内部目标仍有差距；
- 示例评测显示 JD 解析、简历解析和匹配 Accuracy 为 1.0，但数据集每类只有 1–2 个样本，不能作为正式准确率证明；
- 新岗位正式样板、每岗位族样本量、多来源均衡度和正式独立标注集仍未达标；
- 项目使用 DeepSeek 的 OpenAI 兼容接口，可在无模型或未启用模型增强时使用本地规则与可追溯摘要降级；仓库不包含本地大模型权重。

## 安全与数据边界

- 不读取或记录 `.env` 中的秘密值，只保留字段名和 `.env.example`。
- 不提交 `data/job_competency.db`、`data/backups/`、批量原始采集文件和测试临时目录。
- 只保留明确标记的示例、合成数据和可公开说明材料。
- 上传前扫描常见密钥格式、个人信息、大文件和意外纳入的数据库文件。
- Git 历史从本次整理开始，避免把敏感文件写入历史后再删除。

## 验证方案

1. 运行完整测试与覆盖率门禁。
2. 检查文档中数字是否能由数据库或测试输出复核。
3. 在不使用真实 `.env` 的条件下验证基本启动和健康检查。
4. 使用全新读者视角回答项目完成度、架构、流程、输入输出、算法、结果和运行方式等问题。
5. 检查 Git 暂存区文件列表、仓库总体积、敏感信息和大文件。
6. 创建新的私有 GitHub 仓库并推送 `main` 分支，确认远程文件可见。

## 不在本次范围内

- 不修改业务算法或补充尚未完成的功能；
- 不将示例评测包装为正式性能结论；
- 不上传完整生产数据库、数据库备份或未经确认的数据集；
- 不修改或覆盖现有 GitHub 仓库。
